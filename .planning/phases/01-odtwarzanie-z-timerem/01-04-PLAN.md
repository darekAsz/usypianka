## Phase Goal

**As a** parent, **I want to** choose a built-in noise, set a time and start playback, **so that** the sound fades in gently, loops without audible gaps (also with the screen locked) and fades to silence and stops when the time is up.

*(Story assembled from the ROADMAP Phase 1 Goal clauses; the ROADMAP Goal line itself was not rewritten.)*

**This plan's slice:** proof on a real phone that the loop has no audible seam, also with the screen locked (PLAY-02 — the ROADMAP research flag), plus the first audible run of the tracer and a by-ear tuning of the default volume. This gates the player-screen work (plan 01-06).

<objective>
Build a debug-only measurement instrument (LoopProbe on the real PlaybackService pipeline + a spike screen), have the user run the spike on their one phone, decide the loop format (FLAC / WAV / playlist / AudioTrack escape hatch) and tune the default volume, and record everything in 01-SPIKE.md.

Purpose: Gapless looping on real Android decoders cannot be proven at a desk (RESEARCH Assumption A1). The `AudioOutput` seam keeps any fallback a one-class change.
Output: debug/release `AudioDiagnostics`, `LoopProbe`, `SpikeActivity`, debug manifest, START debug-asset override, `01-SPIKE.md`, possibly tuned `VolumeMap` constants / asset format.
</objective>
